TwinSAFE XML 配置生成器

软件操作手册

一、软件简介

本工具用于生成符合 Beckhoff TwinCAT3 Safety Editor 导出格式（TwinCATExport v0.32）的 XML 配置文件，支持安全设备配置、功能块逻辑、通道关联等功能，并提供 TwinCAT 项目解析和安全项目导入功能。

运行环境要求：
  • Python 3.12+（含 tkinter）
  • pywin32（TwinCAT Automation Interface 导入功能需要）
  • Windows 操作系统
  • TwinCAT 3 XAE 3.1+（导入目标环境）

TwinSAFE XML 配置生成器是一款用于创建 TwinCAT3 Safety Editor 导出 XML 文件的桌面工具。通过可视化界面配置安全项目，最终导出符合 Beckhoff XSD 规范的 TwinCATExport XML 文件。

二、启动软件

1 进入软件目录（demo 文件夹）
2 双击运行 main.py 或在命令行执行：python main.py
3 软件主界面打开后，即可开始配置

三、界面布局

软件界面由以下部分组成：

区域说明
顶部工具栏导入 ESI 文件、管理导入设备等按钮
底部工具栏生成 XML、校验 XML、解析 TwinCAT 项目、嵌入 XML 到解决方案、打开项目目录
左侧标签页项目信息、TwinSAFE 组、功能块、别名设备
右侧配置区对应标签页的详细配置内容
底部日志区显示操作日志和状态信息

四、基本操作流程

4.1 配置项目信息

1 点击 项目信息 标签页
2 填写 项目名称（必填）
3 填写 作者（可选）
4 选择 目标系统类型（如下拉选择 EL1918）
5 填写 SafeAddress（安全地址，默认 1）

4.2 创建 TwinSAFE 组

1 点击 TwinSAFE 组 标签页
2 点击 添加组 按钮
3 在右侧配置区设置组属性：
  • 组名称：输入合法的 C 命名（如 TwinSafeGroup1）
  • MapDiag：映射诊断信息（true/false）
  • MapState：映射状态信息（true/false）
  • 注释：可选的文字说明
4 点击 更新组 保存设置

4.3 解析 ESI 设备（可选）

如果下拉框中没有需要的设备型号，可通过解析 ESI 文件的方式导入设备。
1 点击 别名设备 标签页
2 点击 解析 ESI 按钮
3 在文件选择对话框中选择 ESI XML 文件（可多选）
4 系统自动解析设备信息并添加到设备下拉框
5 如果设备已存在，会弹窗提示是否覆盖
导入的设备会自动保存，下次启动软件时自动加载。

4.4 添加安全别名设备

1 点击 别名设备 标签页
2 点击 添加安全别名设备 按钮
3 在弹出对话框中：
  • 从 设备型号 下拉框选择设备（如 EL1918）
  • 系统自动填充设备参数和 IO 通道
  • 设置 别名（自动清理为 C 命名格式）
  • 设置 SafeAddress（设备安全地址）
  • 设置 ConnectionId（连接 ID）
  • 设置 Watchdog（看门狗超时时间，ms）
4 点击 确定 完成添加

4.5 添加功能块

1 点击 功能块 标签页
2 从 FB 类型 下拉框选择功能块类型（如 AND、OR、FBD 等）
3 点击 添加功能块 按钮
4 在右侧配置区设置 FB 属性：
  • 功能块名称：输入合法的 C 命名
  • MapDiag / MapState：诊断和状态映射选项
  • 注释：可选的文字说明
5 点击 更新 FB 保存设置

4.6 配置引脚关联

1 在功能块配置区的 引脚配置 部分
2 勾选需要配置的引脚（启用）
3 对于 输入引脚：
  • 从下拉框选择关联的输入通道（RxPdo，设备状态）
  • 输入变量名（自动清理为 C 命名格式）
4 对于 输出引脚：
  • 从下拉框选择关联的输出通道（TxPdo，设备命令）
  • 可多选关联多个输出通道
通道方向说明：所有设备统一通过 ESI 的 SM 属性判断方向。SM="2" 为输出通道（FB 输出），SM="3" 为输入通道（FB 输入）。

五、生成 XML 文件

1 点击底部的 生成 XML 按钮（或菜单 生成 → 生成 XML）
2 在保存对话框中选择保存路径和文件名
3 点击 保存，生成 XML 文件
4 底部日志区显示生成结果

六、校验 XML 文件

1 点击顶部工具栏的 校验 XML 按钮
2 选择要校验的 XML 文件
3 系统自动进行 XSD 校验并显示结果

七、导入 TwinCAT Safety Editor

1 打开 TwinCAT3 Safety Editor（TE9000 1.4.16）
2 使用导入功能加载生成的 XML 文件
3 手动完成安全设备与物理硬件的关联映射
4 执行安全编译（Safety Build）

八、管理导入设备

1 点击顶部工具栏的 管理导入设备 按钮
2 在弹出窗口中查看所有 ESI 导入的设备
3 可执行以下操作：
  • 删除选中：删除选中的设备
  • 删除全部导入：删除所有 ESI 导入的设备
  • 刷新：刷新设备列表

九、解析 TwinCAT 项目

1 点击底部的 解析 TwinCAT 项目 按钮
2 选择 .tsproj 项目文件
3 弹窗显示检测到的安全设备（含 IoPath 预览）
4 勾选需要导入的设备，选择安全 PLC（单选）
5 点击确定自动创建安全别名设备
IoPath 规则：
  • 安全 PLC IoPath（无 Module 后缀）→ TargetSystemConfiguration
  • 别名设备 IoPath（含 Module 后缀）→ SafetyAliasDevice
  • PLC 的 Local 别名设备不设置 IoPath

十、嵌入 XML 到解决方案

1 点击底部的 嵌入 XML 到解决方案 按钮
2 选择 TwinCAT 解决方案文件（.sln）
3 选择安全项目文件（.xml 或 .tfzip）
4 项目名称自动从 XML 文件读取，确认导入
环境要求：
  • 安装 pywin32（pip install pywin32）
  • TwinCAT 3 XAE 已安装并运行
  • 解决方案中包含 TwinCAT Safety 项目

十一、保存/打开项目

1 保存项目：菜单 文件 → 保存项目 JSON
2 打开项目：菜单 文件 → 打开项目 JSON

十二、命名规则说明

所有名称字段（别名、组名、功能块名、变量名）会自动清理为合法的 C 语言命名格式：

规则说明示例
非法字符替换非字母、数字、下划线的字符自动转为 _InoSV680S-FSoE → InoSV680S_FSoE
合并下划线连续多个下划线合并为一个a__b → a_b
去除首尾下划线首尾的下划线自动去除_name_ → name
数字开头数字开头自动添加 _ 前缀123abc → _123abc

十三、常见问题

Q1: 生成的 XML 导入 TwinCAT 后编译报错？

A: 本工具不校验功能块逻辑，仅保证格式正确。请根据编译提示检查功能块配置和通道关联。

Q2: 设备下拉框没有我要的设备？

A: 可在 别名设备 页面点击 解析 ESI 按钮，导入设备的 ESI 文件，导入后设备会出现在下拉框中。

Q3: 通道方向不正确？

A: 通道方向由 ESI 文件中的 SM 属性决定。SM="2" 为输出（FB 输出），SM="3" 为输入（FB 输入）。如方向不正确，请检查 ESI 文件。

Q4: 名称被自动修改了？

A: 这是 C 命名规则自动清理功能，将非法字符转为下划线，确保名称符合安全工程要求。
